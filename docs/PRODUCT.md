# 随口清单的产品思路

## 让已有的语音输入，多做一步

想起一件事时，打开清单、找输入框、填标题和时间，会打断手头的事。做完之后再回来勾选，也很容易忘记。

很多人已经习惯用语音输入写消息、整理想法。随口清单希望接在这条已有的路径后面：用户照常说话，语音工具负责转写，清单理解其中明确的待办意图。记事和完成都用同一个入口，不再要求用户切换应用或学习第二套录入动作。

它首先面向经常使用电脑、已经有语音输入习惯、需要快速记下零散事项的人。普通转写照常进行，清单识别个人安排、提醒、完成和取消等意图；不要求固定开头，但自然表达仍可能有歧义。

## 核心体验

**一句话记下。** “帮我记录一下，明天有个面试”创建事项；“提醒我明天下午三点面试”同时设置提醒，默认提前 10 分钟。

**一句话勾掉。** “面试完成了”查找清单中几乎完整对应的事项，目标唯一时完成，并取消剩余提醒。完成不是录入的附带功能，它是让清单持续保持真实的另一半。

**沿用原来的入口。** 产品方向是跟随用户语音工具已有的按键或转写入口。当前默认 Fn，是实现选择，不是长期限定。自定义接入仍需尊重操作系统能提供的事件与第三方工具的行为，不能承诺所有物理按键、所有软件都能接收。

**日常保持安静。** 普通转写不弹出清单；成功写入后给简短结果和撤销。只对不明确的部分追问，已完成事项不再追问提醒时间。

## 自然表达优先

不要求记住固定开头。时间可以放前面或后面，提醒可以放句尾，也可以只说个人计划或已经做完的事项。允许用户纠正和删除多记的事项，而不是为了少记错就把表达限制成一种格式。

先用本机规则处理可确定的创建、提醒、完成、取消与简单多事项；本机无法可靠理解时，才使用配置可用的 AI 理解完整上下文。AI 总等待上限 8 秒，可随时停止，迟到结果不执行。无法理解的原话保留，并提供手动整理入口。普通闲聊、引用示例和单个无意义词尽量不收，但无法承诺识别所有意图，也不承诺 AI 永远正确。

对新增保持包容，对会影响已有数据的完成、取消维持完整名称、日期和状态校验。有歧义时选择具体事项，不能猜测或自动覆盖旧安排。

## 哪些决定由用户保留

- 创建同名事项也新增，不自动合并或修改已有内容。
- 修改旧事项的标题、日期与提醒，通过清单中的编辑入口完成。
- 完成需完整名称基本对应且目标唯一；相似、不完整或有歧义的表达要进一步选择，否定和改口不能误完成。
- 明确说要提醒才设提醒；只有事项安排而没有提醒意图时，只记录事项。
- 完成、取消都保留撤销；断网与理解失败保留文字，不显示虚假的成功状态。
- 时间按输入当时的日期和时区解释；事项发生时间与通知时间分别保存和展示。

## 目标与当前版本

理想接入路径是：

```text
已有语音工具与快捷键
        ↓
本次转写文字
        ↓
相关表达筛选 → 本机识别；复杂表达才请求 AI → 校验创建 / 完成 / 取消 → 保存与反馈
```

**当前发布的是这个方向上的 macOS 开发实现。** 它有两个不同的 Fn 路径：

1. 默认路径：复用 Fn，让随口清单自己用 SpeechAnalyzer 在本机识别。原输入法仍独立运行，因此省下额外按键，但没有复用第三方转写结果，也仍需验证同时录音的兼容性。
2. 试验路径：从本次会话对应的输入框或新产生的剪贴板转写取得文字，更接近产品目标，但会受输入法、应用输入框和辅助功能权限影响，存在漏接。

此外保留独立录音与手动文本入口，便于当前设备无法接收时继续使用。它们是备用方式。

当前没有 Windows / Linux 客户端，也未实现任意快捷键录制。已完成的解析与动作规则可以为后续实现提供参考，但现有应用使用 macOS API，跨平台需要真正的适配工作。

## 后续方向

以下均为计划，不是当前功能或交付日期承诺：

- [ ] 完成真实设备验收：原有快捷键 → 语音 / 转写 → 创建与完成；覆盖常见输入框、全屏、取消与超时。
- [ ] 提高外部转写接收可靠性，记录不同语音工具与目标输入框的实测兼容范围。
- [ ] 让用户配置与原语音工具一致的按键或组合键，并验证冲突、按住 / 切换等不同手势。
- [ ] 分离系统相关的输入、持久化和通知实现，探索 Windows / Linux 适配。
- [ ] 在真人语音与提醒送达验收通过后，再提供适合公众安装的发行包。

本阶段聚焦个人清单和一次性提醒。手机同步、重复任务与团队协作不在当前范围。
