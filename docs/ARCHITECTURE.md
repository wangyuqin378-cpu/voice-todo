# 实现结构

原生 SwiftUI + AppKit，最低 macOS 26，无第三方 Swift 依赖。

## 两种语音接入

产品目标是复用已有语音工具与入口。当前 `GlobalHotkey` 被动观察按键，再根据设置进入不同路径；两条共享语音路径使用可配置的 `DictationShortcut`，默认 Fn，独立录音仍可选择右侧 Option / Control / Command。`ShortcutRecorderSheet` 仅在设置面板内录入并消费按键，期间暂停正常接收；保存后继续使用被动监听，不抢走原工具的快捷键。其他操作系统尚未适配。

- **本机识别（默认）**：`FnSpeechCapture` 管理开始、结束、取消和超时，`SpeechService` 用 SpeechAnalyzer 转写。模型准备期间短暂缓存开头音频，缓冲有上限，取消时释放。这条路径复用已配置的语音按键，但不使用第三方语音产品的转写结果。
- **接收输入法文字（试验）**：`InputMethodBridge` 将本次按键会话关联到目标应用与输入框，通过辅助功能与受约束的新剪贴板变化接收转写。拒绝密码框、旧内容及无法关联的上下文，不自动发送或删除其他应用文本。这不是第三方官方接口，兼容性依赖具体语音工具与目标输入框。

手动及长文本输入直接进入相同的文字处理流程。两个语音路径的系统能力、权限与验收需求独立，不能用其中一条的成功证明另一条可靠。

## 从文字到结果

1. `AutomaticCapturePolicy` 筛选具有事项意图的表达，不限制关键词位置。输入框、剪贴板、Fn 本机识别和应用入队使用相同规则；短回答需要仍有效、绑定来源的追问上下文。普通聊天不持久化、不调用 AI，手动输入 / 独立录音视为主动提交。
2. `Repository` 先持久保存候选文字、唯一输入 ID、输入日期、时区和追问快照。
3. `LocalInterpreter` / `OfflineInterpreter` 先解析完整输入并校验提案；成功时不读取 Key、不调用 AI。本机无法可靠处理时，才在配置与凭证可用、未处于失败暂停的前提下请求 AI。无法处理则保留原话供手动整理，`TaskReducer` 独立校验日期、任务 ID、状态、完成 / 取消证据及问题归属，再原子写入。
4. 提交成功后显示结果，`NotificationService` 核对系统通知。

旧自动队列按当前意图规则复核；没有相关意图的文字保留给用户核对。混合表达在副本上一次性校验、提交，不执行半段。

`AIRequestDeadline` 给整次 AI 理解和连接检查设置 8 秒上限，包含协议兼容重试。超时或用户停止等待时取消请求、释放处理队列；即使服务忽略取消并返回，迟到的结果也会被丢弃。使用一次性 continuation 竞争而非等待所有子任务退出，避免非协作请求继续阻塞调用者。

AI 不能直接写数据。失败保留输入；重试不重复执行。处理期间清单改变则拒绝使用过期快照。明确完成和取消使用完整本地索引校验，不依赖模型“置信度”。

## 事项与提醒

`plannedAt` / `plannedHasTime` 表示事项日期和是否具有时刻；`reminderAt` 表示通知时间。提前提醒从事项时间计算，重复调用不会再减一次。相对日期以输入发生时的当地日期为准；实际触发的即时提醒在处理完成时重新计算。

独立新增永远不合并同名任务。`setReminder` 只用于补齐尚未完成的创建问题；已有任务的修改从人工表单进入。完成和取消移除相应系统提醒，撤销恢复时必要地分配新提醒代次，避免旧送达记录阻止恢复后的提醒。

通知队列选择最早 60 条，保留有效已有请求，移除过期代次和不在窗口的请求。权限关闭不把消失的请求当作已送达。请求成功仅代表提交给系统，实际展示需要设备验收。

## 本地持久化

SwiftData 保存任务 payload、元数据和输入记录。任务协议、追问、撤销为 Codable 值，Reducer 在副本上操作；校验失败不写半套结果。数据库保存失败回滚。自动保存关闭，应用显式提交。

`CaptureRecovery` 对比输入当时的问题及任务快照，防止旧“是的 / 第一条”在上下文变化后执行。原话直接重试保留日期；修改后保留原始信息并更新解释时间。

## 测试与人工验收分工

- Core：解析、日期、提前量、完成 / 取消证据、否定、改口、重试和撤销。
- App：状态回调、录音边界、恢复、模拟通知中心、设置持久化、隐私诊断。
- 显式联网：合成任务与真实已配置模型，检查多轮对话和混合表达。
- 人工设备：物理 Fn、真实麦克风、其他输入法同时录音、全屏、睡眠 / 唤醒、通知实际出现、30 条真人表达的准确率和延迟。

测试替身和文本验收不代替最后一项。截图证明可见状态，不证明后台交付或完整辅助技术可访问性。

## AI 协议与运行状态（build31）

`AIConfiguration` 区分 Chat Completions 与 Anthropic Messages。旧配置解码时默认自动；根据 endpoint 决定格式，不根据 Key 或模型名猜服务商。请求保持原 endpoint / model；官方百炼与 DeepSeek 才携带其专属参数。Claude 使用 `/v1/messages`、`x-api-key`、`anthropic-version` 和独立 system 字段，不发送 Chat JSON mode / temperature / 厂商 thinking 参数。依据 [Claude Messages 官方协议](https://platform.claude.com/docs/en/api/messages/create) 与 [DeepSeek 官方协议](https://api-docs.deepseek.com/api/create-chat-completion/) 实现。

`AICompatibility` 只在 400 / 422 明确拒绝已知可选参数时调整一次，成功解码后缓存能力；不会在 401 / 403 / 404 上尝试别的模型或服务商。不支持的 response_format / thinking 参数可以去除，明确提示的 max_tokens 可转换成 max_completion_tokens；输出仍需完整 JSON 和 reducer 校验。不会从自由文本中截取局部 JSON 执行。

`AIHealth` 以配置和 Key 的内存摘要隔离运行状态。认证 / 明确配置错误暂停至配置变化或手动检查成功；网络 / 限流 / 临时 / 非法响应错误暂停 60 秒后允许下次输入重试。任务动作本身被 reducer 拒绝不会禁用服务。健康状态与能力缓存均不落盘，重启后重新尝试；不记录 Key、服务响应正文或原话。连接检查只接受非空 noop 动作，不会更改任务，新配置仅在检查通过后保存。

## 自定义语音按键

`DictationShortcut` 保存触发键、修饰键及显示标签；损坏或无效配置回退为 Fn。`DictationShortcutGesture` 只保留当前按住状态：完整组合开始，首次释放结束，多余按键 / Esc 取消；按住重复、取消后迟到释放、重置后的自动重复不能创建新会话。默认 Fn 保留原有的完整按下周期取消规则。

录入只监听设置面板的前台事件，不保留键盘历史。切出面板清除未完成的录入，取消保持旧配置，切换配置清理正在进行的录音和追问来源。按键标签同步到设置、接收状态和追问提示。
