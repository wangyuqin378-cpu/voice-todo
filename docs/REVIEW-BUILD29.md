# 2026-09-17 · build29 提醒名称同步

对象：随口清单 0.1.1 / build29。

## 发现的问题

手动修改事项标题后，清单显示新标题，但已排队的系统通知仍保留旧标题。原因是通知调度只检查请求标识是否存在，没有检查内容是否变化。

## 修复

- 待发送的提醒名称变化时，用同一标识更新通知内容，保留原定时间。
- 更新失败时保留原提醒，显示安排失败提示，下次核对继续尝试。
- 已过发送时刻或已有送达记录的提醒，不因改名重新发送；重启后同样保留这一限制。
- 不改变事项的提醒版本，不重新生成已送达的提醒。

系统允许同一标识替换待发送请求；同一标识若已送达，则重新提交会再次提醒。因此本次修复保留了对发送时刻与送达记录的检查。[Apple 接口说明](https://developer.apple.com/documentation/usernotifications/unnotificationrequest/init(identifier:content:trigger:))

## 验证

- 修复前新增回归用例复现旧标题未更新的问题。
- 修复后共 **269 项测试，264 项通过、5 项显式联网测试跳过、0 失败**。
- 新增覆盖：改名同步且时间不变；更新失败保留原提醒并重试；已过发送时刻、已送达和重启后不因改名重复提醒。
- 发布构建和本地签名验证通过。本轮尚未安装到日常使用的应用。
