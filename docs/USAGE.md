# 使用指南

当前版本：0.1.1 / build36，macOS 26 开发版。获取源码和构建步骤见 [项目首页](../README.zh-CN.md#构建并打开)。

## 第一次使用

1. 打开菜单栏中的随口清单，进入设置 →「语音入口与诊断」。新安装默认「本机识别」，语音按键为 Fn。
2. 授予输入监控；本机识别模式授予麦克风权限，并检查 / 安装简体中文 SpeechAnalyzer 模型。接收输入法文字模式需要辅助功能权限。需要通知时允许系统通知。
3. 在清单输入框先试一句“提醒我明天下午三点面试”，检查事项日期与提前提醒时间。文本支持长段输入，按 ⌘ Return 处理；未提交草稿会保留。
4. 再体验语音：默认 Fn 模式轻按开始、再按结束；也支持按住说话、松开结束。Esc 取消。开始回答追问时停止播报。

普通转写保持安静。没有弹窗不一定表示快捷键没有触发；识别到事项操作并写入成功后才反馈。首次体验请用明确表达，并实际检查清单结果。

**不填 API Key 也能使用。** 本机规则支持常见的创建、完成、取消、撤销、日期提醒和简单混合表达；也能直接手动添加、编辑或勾选。这些简单操作不读 Key，也不等网络。只有本机无法可靠理解时才使用配置好的 AI；包括参数兼容重试在内，最多等待 8 秒，可随时点「停止等待」。超时或取消后，迟到的回答不会改动清单。仍不能理解时原话保留，进入「未处理记录」修改或「手动添加事项」，无需先配置 AI。

默认 AI 服务为阿里云百炼 `qwen-flash`。**Flash 是模型名称的一部分，不是所有服务必须提供的模式。** AI 需要配套的 Key、接口地址、接口类型和可用模型；不能只换 Key 后沿用另一个服务的模型。

在设置 →「更换 AI 配置」填写服务商提供的地址、模型和 Key，检查通过后保存。支持 OpenAI 兼容的 Chat Completions 与 Claude / Anthropic Messages 两类接口。自动模式按官方 Claude 地址或 `/messages` 路径识别 Messages；其他地址按 Chat Completions 处理。第三方中转服务请按其文档选择接口类型，不能根据模型名字推断中转协议。官方 Claude 地址可填 `https://api.anthropic.com/v1`，模型填你账户实际可用的名称，不要沿用 `qwen-flash`。应用不会更换模型或把 Key 发往其他服务商试用。其他专有接口（例如仅支持 Responses、Bedrock 或 Vertex 的接口）需后续适配。

已知服务只发送对应的专属参数；如果通用接口明确拒绝 JSON 模式等可选参数，会在相同地址与模型上调整一次，并在本次运行内记住成功的格式。仍无法解析的结果不会直接写入清单。

密钥无效、权限不足或明确的接口 / 模型配置错误会暂停该配置；断网、限流、临时故障或响应格式错误暂停 1 分钟，之后下一次需要 AI 的输入再试。简单事项始终在本机处理；复杂输入受阻时会显示原因，可点入设置。修改配置 / Key，或手动「检查当前连接」成功后恢复。状态保留在内存，重启应用后会重新尝试一次。

Key 仅用于自己的设备，不包含在源码或应用中。连接检查成功只说明接口可用，不代表语音或提醒已经验收，也不保证模型永远准确。

## 选择入口

- **本机识别（默认）**：复用已配置的语音按键，应用独立使用 SpeechAnalyzer。原输入法保持自己的行为，随口清单不读取或删除其他应用文字。同时录音的兼容性需在你的设备验证。
- **接收输入法文字（试验）**：照常使用原来的语音工具，由随口清单在本次会话中读取当前输入框或新产生的剪贴板转写。不会自动发送或删除其他应用的文字。密码框、不支持读取的输入框、无法明确关联的剪贴板内容可能无法接收。
- **独立录音**：可以选择右侧 Option / Control / Command，或点击清单中的录音按钮。

设置 →「录入按键」可以换成原语音工具的按键或组合键：按下并完全松开，再点「保存按键」。支持 Fn、单独的左右修饰键、功能键、普通键及带修饰键的组合；Esc 用于取消，Caps Lock 和多个普通键组成的组合不支持。取消录入不会修改原配置，也可点「恢复 Fn」。设置仅保存随口清单的监听按键，不会替你修改原语音工具。

设置录入期间暂停接收语音。保存后默认 Fn 的轻按 / 按住方式同样适用于新按键；多个键组成的组合松开其中一个即结束本次按住。只监听完整的组合，多余按键会取消这次接收。系统占用、硬件媒体键或语音工具吞掉的事件可能无法监听；单独字母会在普通打字时触发，请与原语音工具使用相同组合。

当前界面已验证组合键录入、取消、保存、重启保留、启动录音和 Esc 取消；这不代表所有外部语音工具、输入框和键盘已兼容。

保留默认 Fn 时，按住 Fn 后再按 Command、Option、Control、Shift 或普通按键，会取消本次录音 / 接收；即使先松开其他键也不会提交已有转写。全部松开后，可以重新单独按 Fn。正常松开 Fn 后输入法使用粘贴插入最终文字的流程仍受支持。

本机录音只在主动触发期间使用麦克风，单次最多 90 秒；取消或收尾后停止，不持久保存原始录音。其他语音产品自己的录音行为不由随口清单控制。

## 可以怎么说

无需固定开头，也不用先叫清单。下面都是可以进入理解流程的表达；有 AI 时更能处理口语、组合表达和改口，无 AI 时支持的说法较少。

| 语音表达 | 行为 |
| --- | --- |
| 明天下午一点面试，提醒我一下 | 新建面试，事项时间 13:00，默认 12:50 提醒 |
| 我10月1号要买车票，提醒我一下 | 新建买车票；只有日期时默认当天 09:00 提醒 |
| 明天下午一点面试，提前半小时提醒我 | 按明确要求在 12:30 提醒 |
| 后天下午一点面试，明天下午三点提醒我 | 事项时间和提醒时间分别保存 |
| 我明天有个面试 | 只记下，不自动提醒 |
| 如果我想住两天水屋呢，再帮我安排一下 | 讨论方案，不记下、不弹窗 |
| 帮我规划一下明天的旅行路线 | 请求建议，不记下 |
| 在海边住两晚这件事，帮我记一下 | 明确记事请求，可以记下 |
| 材料交好了 | 名称完整对应且唯一时完成「交材料」 |
| 帮我取消明天下午六点的面试 | 唯一匹配标题和事项时间时取消，可撤销 |
| 撤销 | 撤销最近一次清单操作，包括相应提醒 |

一般会处理个人安排、时间加事项、提醒请求、完成或取消陈述；普通聊天、引用例句、单说“土地”等不处理。这是意图筛选，不是口令规则，不能覆盖所有表达。多记时可在「…」中取消；不确定的完成或取消需要你选具体事项，避免影响错误记录。

“如果 / 假如 / 要是……”等假设和询问方案的表达会结合整句话判断，不能只凭“安排”或末尾提到的活动创建。已识别的讨论在本机忽略，不读 Key、不请求 AI；写入前也会独立检查。仍允许在句中或句尾明确要求记事，例如“如果下雨就带伞，这件事帮我记下”；这类条件性备忘不等于支持天气等条件触发通知。未覆盖的含蓄表达仍可能误判，多件事夹杂讨论也需要核对。

新增不会合并或改写同名旧事项；语音要求修改已有日期、标题或提醒时，会引导手动编辑。完成匹配有意保守：“材料交了”不能自动完成「交签证材料」。相似或同名事项会追问，没有原事项且完成内容明确时可以补记完成。

## 提醒、追问与恢复

设置 →「有具体时间时」可选择提前 5、10、15、30、60 分钟或到时提醒，默认提前 10 分钟，仅影响新事项。原话中的明确提前量优先；如果处理时已进入提前窗口，则立即安排提醒。只有日期的提醒默认当天 09:00。

要求提醒但时间不足时，先保存事项并追问。在刚提出问题后的同来源下一次语音中，可直接说“明天下午三点”或“不用提醒”（回答窗口为 2 分钟）。窗口过期、切换来源或已进行其他转写后，请在列表继续该问题；也可明确说“清单，…”接续当前问题。关闭浮窗或重启不会抹掉已保存的追问。

菜单栏清单有待办 / 已完成、搜索、勾选和恢复。每行「…」中可编辑标题与时间、关闭提醒或取消事项。断网、解析或校验失败会保留为「未处理记录」：原话重试沿用当时日期和时区；修改后提交以这次时间理解相对日期。重试不会重复执行同一份输入。手动整理时原话继续保留，全部整理后可忽略记录；已经保存的事项不会因升级而自动删除。

完成、取消或关闭提醒会立即请求移除已知系统提醒，不等待权限界面刷新。旧调度停止继续添加；已在提交中的失效提醒会在提交返回后撤回。系统在取消前已经显示的提醒无法保证用户没看到。撤销时重新安排；恢复已过期事项会补一次提醒。通知权限关闭时会明确提示，重新开启后核对遗漏。

系统队列优先放最近 60 条；更多事项需要应用持续运行以补充。退出应用后，已交给系统的通知仍由 macOS 管理，但专注模式、睡眠、锁屏与系统设置会影响实际显示。

权限允许期间，到时且消失的系统请求会按已处理记账，以避免用户清除通知后反复弹出。这不能完全区分系统丢弃和用户清除，**提交成功或内部“已处理”不等于通知实际送达**。

## 没有记下时

1. 说明具体事项，例如“我明天下午三点面试，提醒我一下”，无需固定开头。只有时间或“是的”等短回答，需要有效的追问上下文。
2. 打开清单，检查是否有「未处理记录」或待回答的问题。若有，查看原因后重试或修改。
3. 在设置的「语音入口与诊断」检查当前模式和权限。输入法成功转写不等于随口清单已经收到文字。
4. 外部转写接收仍是试验功能。可把同一句文字粘进清单验证任务理解，或切换本机识别 / 独立录音，再分别检查结果。
5. 报告问题时附版本、输入模式、语音软件、目标应用和脱敏后的表达，区分“没有收到文字”和“收到文字但处理错误”。

不要因为 AI 连接成功、权限显示开启或测试通过，就假定物理按键、真实转写与通知已经正常。完整验收清单见 [审阅记录](REVIEW-BUILD30.md)。

## 数据与备份

- 任务、原话、追问、失败记录和最近 30 次撤销保存在 `~/Library/Application Support/VoiceTodo/`。偏好与未提交草稿位于应用的 macOS 偏好设置中。
- 简单事项在本机处理，不调用 AI。只有本机无法理解且配置可用时才调用 AI，会发送当前文字、清单中的标题 / 日期 / 完成状态及必要追问上下文到你配置的服务。完整索引过大时会明确失败，不假装“没有找到”。随口清单不上传原始录音。
- 手动填写的密钥存系统钥匙串。可显式引用本地 DeepSeek 配置，但该密钥仅用于官方 DeepSeek 接口，不写入源码或任务日志。
- 接收输入法文字只围绕当前转写会话，拒绝旧剪贴板或无法明确关联的内容。诊断仅保留有限的接收阶段、时间和应用标识，不记录转写、任务标题、其他键盘输入或剪贴板内容。
- 使用其他语音工具时，它们的录音与上传策略由各自设置决定。

备份前先退出应用，再复制整个数据目录，包括 `.store` 的附属文件。恢复旧备份会覆盖备份后的任务，需要自行核对。
