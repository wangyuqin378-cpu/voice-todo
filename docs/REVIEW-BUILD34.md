# build34：Fn 组合键取消与提醒验收记录

日期：2026-09-18。版本：0.1.1 / build34。

## 发现与修复

旧版仅在 Fn 自身变化或普通按键按下时检查组合键。按住 Fn 后再按 Command、Option、Control 或 Shift，如果先松开修饰键，再松开 Fn，就可能把此次录音正常提交。本机识别和接收输入法文字共用这个入口，因此都受影响。

现在跟踪完整的一次 Fn 按下 / 松开：出现组合键后，本次接收立即取消，直到松开 Fn 都不能提交。先按修饰键、先按 Fn、不同松键顺序均被覆盖。重复按下不重复启动，无对应按下的松开不结束录音；睡眠或重置后，在重新按下前收到的旧松键也会被忽略。下一次正常 Fn 仍然可用，松开 Fn 后输入法的正常粘贴提交流程不受影响。

## 验证证据

- 修改前，3 项新增回归测试失败，共 17 处断言失败，复现组合键漏取消、重复按下和无对应按下的松开被传递。
- 最终离线套件：316 项，309 项通过，7 项显式联网测试跳过，零失败。本轮没有修改 AI 逻辑，不重复进行真实模型请求。
- 新增按键测试覆盖四种修饰键、不同按下 / 松开顺序、原有普通按键尚未松开、重复事件、重置及丢失按下事件后的 Fn 组合键。
- 本机识别集成测试：以“材料交好了”作为正在识别的片段，加入组合键后，不结束转写、不完成原事项、不读取 Key、不弹窗、不留下未处理记录；随后正常 Fn 输入可以完成同一事项。
- 外部输入法集成测试：组合键取消后，迟到的输入框文字和剪贴板内容都不提交；下一次正常会话可以接收新提醒。
- 这些测试走实际应用处理代码和隔离的语音 / 桌面替身，不发送系统按键，不使用日常任务数据，不能代替真人语音及真实键盘验收。
