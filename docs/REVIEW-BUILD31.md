# build31：AI 服务兼容与失败恢复

日期：2026-09-17。版本：0.1.1 / build31。

## 问题和变化

“配置 Key 后优先 AI”需要同时满足服务地址、接口协议、模型和凭证匹配。旧版全部使用 Chat Completions 格式，并且每次输入都会再次尝试失效的配置；`qwen-flash` 只是默认模型，并非通用模式。

- 新增 Claude / Anthropic Messages；保留 OpenAI 兼容 Chat Completions。自动判断官方 Claude 地址，第三方服务可手动选择协议。模型由用户填写，不依据 Key 猜模型，不自动换供应商。
- 只对已知官方服务发送专属参数；Claude 不发送 Chat JSON mode、temperature 或其他厂商的 thinking 参数。已验证的官方百炼 / DeepSeek 参数继续保留。
- 服务明确拒绝可选参数时，在同一地址、模型上调整一次；成功的格式在本次运行中复用。认证或找不到模型不触发该重试。
- 密钥 / 明确配置错误暂停调用，避免每条输入重复失败；网络、限流与非法响应暂停 60 秒。期间继续使用本机规则，并显示原因。更换配置或 Key、手动检查成功后恢复，重启会重新尝试。
- 检查连接必须得到非空 noop 结果，才允许保存新配置；检查不会写入任务。AI 提案仍需本机验证，连接成功不等于每条理解准确。
